fix(clock): treat slave_clock_wait time as relative duration

22a4d6e | google-labs-jules[bot] | 2026-06-10

The `zst_clock_wait` API expects a relative duration in nanoseconds when working with clock slaving, not an absolute timestamp. `slave_clock_wait` was treating the relative wait duration as an absolute timestamp and subtracting the `base_master` from it, causing the final calculated sleep duration in the reference clock to be incorrect and drift dramatically when the master and reference clocks had significantly different base times. This fix correctly interprets the requested time as a duration by dividing it by the drift ratio `alpha` to get the required duration in the reference clock's domain.
